## 2026-10-13 — B1b：verify 脚本进程生命周期修复

### 背景

`server/verify-*.ts` 系列验证脚本原本用
`spawn('npx', ['tsx', 'src/server.ts'], { shell: true })` 启动被测服务。
在 Windows 下这会插入 `cmd.exe` 外壳，形成 4 层进程链
（`npx-cli` → `cmd.exe` → `tsx cli` → `node(preflight)`）。
脚本手上的 `proc` 指向最外层，`proc.kill()` **只能杀掉外壳**，内三层逃逸为孤儿进程。

### 本项工作做了什么

1. 新增公共生命周期模块 `server/harness/server-lifecycle.ts`（537 行）。
2. 用该模块改造 1 个代表脚本：`server/verify-phase3-search.ts`。
3. 改造 4 个 recipe 验证脚本：`verify-recipe-batch1/2/3.ts`、
   `verify-recipe-transaction-rollback.ts`。
4. 为上述 4 个脚本新增测试数据库路径隔离入口 `HOME_CHEF_TEST_DB_DIR`。
5. **收尾批次**：为 `server/verify-phase3-search.ts` 补上同一隔离入口
   （它是阶段 1 的代表脚本，此前"已接入 harness 但仍会写入 `server/data/`"）。

### 结论摘要

- 4 个 recipe 脚本 + 代表脚本均已接入公共 harness，服务启动**不再经 shell**。
- 4 个 recipe 脚本 + `verify-phase3-search.ts` 的测试数据库已可重定向到 `%TEMP%`，
  并各在独立隔离目录中跑通一次（`PASS=83/103/106/27/39`，`FAIL` 全为 0，退出码全为 0）。
- **未做**：全量回归；其余 19 个仍用旧式 `npx + shell` 启动服务的脚本；
  `StartServerOptions.env` 的设计问题；`seed` 子进程的 `shell: true`。

详细证据（命令、退出码、PASS/FAIL、保护范围核对）见
[`dev-notes/B1b-harness-lifecycle.md`](dev-notes/B1b-harness-lifecycle.md)。
